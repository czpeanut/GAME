# 學姊問答

輸入問題，Gemini 回答，學姊把答案唸出來，嘴型跟著真實語音走。三欄式版面：左側對話紀錄、中間人偶、右側對話串。

角色、動態骨架、介面配色都跟故事遊戲那邊同一套——她站在同一間教室前面，用同一組奶油／玫瑰色調。

> 完整的技術決策過程、試過並放棄的方案、已修復 bug 的根因、還沒解決的問題，見 [`DEVELOPMENT.md`](./DEVELOPMENT.md)。要合併這個 repo 到其他專案之前建議先看過。

## 技術架構

- **問答**：[Gemini API](https://ai.google.dev) 產生答案。系統指令要求它用簡短口語回答、不要 Markdown 或 LaTeX，因為答案會被直接唸出來；後端另有一層清洗當保險。
- **語音**：Gemini 的 TTS 模型（預設聲線 `Leda`，Google 文件標為 *Youthful*；頁面上可以試聽換掉）。**回答會先拆成句子，一句一句合成**，第一句拿到就開始講，後面的在播放中途先要好。可以串流的模型（3.1 以後）還會邊生成邊送，瀏覽器邊收邊播。
- **畫面**：Canvas 上的**剛體切塊人偶**——十層真正的分層素材（長髮、裙子、舉起的手、瀏海、眼睛、嘴型⋯⋯），各自有關節和彈簧，會呼吸、微傾、眨眼、頭髮和裙子延遲擺動，背後是同一張教室背景。沒有任何第三方服務、沒有 WebRTC、沒有授權費。
- **嘴型**：即時量音量（每 20ms 一格）決定嘴巴閉合／半開／張開。不是隨機開合，是跟著真的在說什麼走；因為是即時的，所以音訊還在傳的時候嘴巴就能動。關鍵不在「張開得夠不夠快」，而在**閉得夠不夠快**——句子裡兩個字之間只有約 70ms 的空檔，嘴巴要來得及在那裡閉上，否則整句話看起來就是一直開著在拍。細節見 `public/src/puppet/lipsync.js`。
- **速解法**：問題送出時先比對關鍵字，命中的題型會把老師寫好的標準做法交給模型（要它照著講），同時把公式原樣顯示在畫面上。見下面「速解法」一節。
- **後端**：Node.js + Express，只做三件事：比對速解法、呼叫 Gemini 取得答案、呼叫 Gemini TTS 取得語音（金鑰全部留在伺服器端）。

## 為什麼不用第三方虛擬人服務

前一版用的是 [Simli](https://www.simli.com) 的即時串流虛擬人：把照片送上去建 avatar，播放時把音訊餵過去、透過 WebRTC 取回嘴型同步的影像。換掉的原因：

| | Simli 串流 | 現在的人偶 |
|---|---|---|
| 每次回答的外部往返 | 建 session token ＋ 整段 WebRTC 串流 | 無 |
| 開場等待 | 要先連線才能發問（手機上常失敗） | 直接就能問 |
| 費用 | 免費 50 分鐘／月，超過按量計費 | 0 |
| 素材 | 需要清晰正臉照片 | 需要拆好的角色立繪部件 |
| 風格 | 真人照片 | 可以是任何畫出來的角色 |

代價是嘴型只有三段（閉合／半開／張開），不是真的音素對嘴。實測在這個尺寸下看不太出來——會動的是嘴、閉合的時機對得上句子的停頓，這兩件事到位就夠了。

不過「對得上」是要量的，不是看感覺。`npm test` 裡有一段用已知的音量波形餵嘴型模組，量它在 6 個音節空檔裡閉上幾次、總共張開了多久；`npm run test:browser` 則是真的音訊、真的 AnalyserNode、真的 canvas，每一幀記一次嘴型。換掉成串流合成之後這兩個數字掉得很兇（真實音訊下一秒只閉 0.7 次、88% 的時間都是開著），現在是一秒閉 4.4 次、65%。

## 事前準備

1. Node.js 18 以上
2. 一組 [Gemini API key](https://aistudio.google.com/apikey)（問答與語音共用同一把）

沒了。不需要第二個服務的帳號，也不需要事先建立 avatar。

## 安裝與設定

```bash
npm install
cp .env.example .env    # 填入 GEMINI_API_KEY
npm run build
npm start
```

開啟 `http://localhost:3000`。

## 測試

```bash
npm test               # 嘴型、斷句、速解法比對的單元測試（純邏輯，不需要瀏覽器）
npm run test:browser   # 端對端：起真的 server、開 Chromium，串流和退回兩條路徑各跑一次
```

瀏覽器測試會自己啟動 server，**並且啟動一個假的 Gemini**（`test/fake-gemini.mjs`）讓 server 真的去打——所以串流的 SSE 解析、長度未知的 WAV、瀏覽器邊收邊播，這些都是真的被測到的，不是用假資料繞過去。不需要 API key，也不會花到錢。沒裝 playwright 或找不到 Chromium 時會直接跳過。

## 換成別的角色

人偶的素材規格和拆分工具在這個 repo 的根目錄（`tools/split-parts.py`、`tools/cut-variants.py`，說明見根目錄 README 的「動態立繪：素材拆分規格」）。換角色要做的事：

1. 把部件圖放進 `public/assets/characters/<新角色 id>/<部件>/<變體>.png`
2. 改 `public/src/puppet/hero.js`：角色 id、關節位置（`pivot`，每個角色各自量）、名字
3. `npm run build`

沒提供的部件會自動跳過，可以一張一張補。目前 `eyes` 還沒有素材，所以人偶不會眨眼。

## 部署到 Render

在 [Render](https://render.com) 點 **New +** → **Blueprint** → 選這個 repo → 分支選 `claude/speaking-puppet` → **Apply**。環境變數只需要 `GEMINI_API_KEY`。

**`render.yaml` 在 repo 根目錄，不在這個資料夾裡。** Render 只從 repo 根目錄讀這個檔，不會去子資料夾找——所以藍圖放在根目錄，用 `rootDir: speaking` 指回這裡，`npm install`、建置、啟動都在這個資料夾裡跑。

如果把這個資料夾單獨拉出去變成自己的 repo，把根目錄那份 `render.yaml` 搬過來，並刪掉 `rootDir` 那一行。

**注意**：免費方案閒置約 15 分鐘會休眠，下次有人造訪要等十幾秒到一分鐘的冷啟動。

## 可調整的環境變數

| 變數 | 預設 | 說明 |
|---|---|---|
| `GEMINI_MODEL` | `gemini-3.6-flash` | 回答問題用的模型 |
| `GEMINI_TTS_MODEL` | `gemini-2.5-flash-preview-tts` | 退回時用的語音合成模型（一次回傳） |
| `GEMINI_TTS_STREAM_MODEL` | `gemini-3.1-flash-tts-preview` | 可串流的語音模型；設成空字串會強制走上面那個 |
| `GEMINI_TTS_VOICE` | `Leda` | 預設聲線。Google 的文件只給每個聲線一個風格字（Leda 是 *Youthful*、Zephyr 是 *Bright*、Sadachbia 是 *Lively*⋯⋯），**沒有標性別，也沒有標年齡**——所以這件事只能用耳朵決定，不能從清單上讀出來。頁面上有試聽的選單（見下），選定之後把結果寫回這個變數就會變成新的預設 |
| `GEMINI_TTS_TONE` | `lively` | 預設語氣：`lively`（活潑）/ `gentle`（溫柔）/ `calm`（沉穩）/ `default`（不加指示）。這些不是 API 參數，是加在文字前面的一句中文指示 |

## 速解法：老師先寫好的標準做法

有些題型是有「標準打法」的，老師知道那個打法，而一個通用模型每次被問都會生出一套稍微不同、有時候還微妙地錯的做法。所以這些題型改成**先比對、再回答**：

1. 學生送出問題時，伺服器拿問題去比對 `content/quick-methods.json` 裡的規則。
2. 命中的話，那一則速解法會放進送給 Gemini 的系統指令裡，要它**照這個方法講，不要自己另外想一套**。
3. 同一則的公式和步驟**原樣顯示在畫面上**，不經過模型改寫。

第 3 點是刻意跟第 2 點分開的：回答會被唸出來，而公式唸出來沒有人聽得懂（「R 等於根號 a 平方加 b 平方」沒有人跟得上）。所以**講的是方法，顯示的是符號**，模型還會被告知畫面上有步驟、可以叫學生看一下。速解法卡片永遠不會被送去語音合成——測試有守這一條。

目前內建三則：三角函數疊合（輔助角公式）、二次函數配方求極值、等差數列求和。

### 新增一則

改 `content/quick-methods.json` 就好，**不用動程式**，重開伺服器就生效：

```json
{
  "id": "log-rules",
  "title": "對數運算",
  "rules": [["對數", "化簡"], ["log", "換底"]],
  "exclude": ["自然對數的歷史"],
  "formula": "log_a(b) = log_c(b) / log_c(a)",
  "steps": ["先統一底數。", "再把乘除拆成加減。"],
  "example": "log_2(8) = 3",
  "note": "可選"
}
```

- `rules` 之間是**或**：任何一條命中就算命中。
- 一條裡面的詞是**且**：全部都要出現。所以 `["sin", "cos", "最大值"]` 是「三個都要有」，這是避免 `合成`、`最大值` 這種太泛的字自己亂射的辦法。
- 比對前會把全形轉半形、英文轉小寫、空白全部拿掉，所以 `ａ　ｓｉｎ　θ` 和 `asinθ` 是同一個東西。
- `exclude` 裡任何一個詞出現，這一則就不算命中。
- 一個問題最多帶兩則（`MAX_MATCHES`）。命中三則以上通常代表規則寫得太鬆，不是學生真的問了三件事。

**新增之後請在 `test/quick-methods.test.mjs` 補上該命中和不該命中的句子。** 誤判貼出一張不相干的速解法，比沒有速解法還糟，而那件事只有測試抓得到。

## 聲線怎麼挑

Gemini 有 30 個內建聲線，文件只給每個一個風格字，**沒有標性別也沒有標年齡**。這種東西不可能靠讀清單決定，所以人偶旁邊的控制列有兩個選單和一顆「試聽這個聲音」：

- **聲線**：30 個都在裡面，`★` 標的是文件上寫著年輕／明亮／活潑的那幾個（Leda *Youthful*、Zephyr *Bright*、Autonoe *Bright*、Laomedeia *Upbeat*、Sadachbia *Lively*、Aoede *Breezy*、Achird *Friendly*、Zubenelgenubi *Casual*）——那是「從哪裡開始聽」，不是答案。
- **語氣**：活潑／溫柔／沉穩。這一個往往比換聲線有感，因為它改的是講法而不是音色。跟語速一樣，是加在文字前面的一句中文指示（`請用活潑開朗、充滿精神的語氣說：⋯⋯`），模型會照著演而不是把它唸出來。

試聽只合成一句話，不會動到問答額度。選定之後把 `GEMINI_TTS_VOICE` 和 `GEMINI_TTS_TONE` 設成那一組，新的訪客一進來就是那個聲音。

清單來自 `server.js` 的 `VOICES`，經 `GET /api/voices` 給頁面，所以只有一份。`/api/tts?voice=&tone=` 只接受清單裡的值，不認識的直接 400——這兩個參數會進到送去 Gemini 的請求裡，不能照收。

## 延遲是怎麼壓下來的

原本一個回答要等 7～17 秒才出聲，因為它等的是「整段回答的語音」——而那是最慢的一種等法。現在改成三件事疊在一起：

1. **拆句子。** 回答切成子句，只有**第一句**是要等的，後面每一句都在前一句播放的時候先去要。第一句還有更緊的長度上限（24 字，約兩秒的語音），因為它是唯一有人在等的那一句。
2. **兩個 `<audio>` 輪流用。** 一個元素只能緩衝一個來源，所以下一句需要自己的地方可以先收。
3. **會串流的 TTS 模型。** Gemini 從 3.1 版起的 TTS 可以邊生成邊回傳（`gemini-3.1-flash-tts-preview`），伺服器收到第一塊就開始往瀏覽器送，WAV 檔頭先出去、長度寫成「讀到結束為止」。

⚠️ **串流模型是 preview**，不保證每一把 key 都拿得到。拿不到的時候會**自動退回**原本一次回傳的 2.5 模型，功能照常，只是慢一點。想知道實際走哪條路，看 `/api/tts` 回應的 `X-TTS-Path` 標頭，或看伺服器日誌：

```
TTS 串流 首段 412ms（23 字）      ← 走串流
TTS 一次回傳 3120ms（23 字）       ← 退回一次回傳
```

瀏覽器 console 也會印「第一句語音：送出後 X 秒」——那是唯一真正重要的數字。

把 `GEMINI_TTS_STREAM_MODEL` 設成空字串可以強制走一次回傳的路徑。

## 已知限制

- 嘴型是三段音量對應，不是音素對嘴——聽起來對得上，但不會有 ㄅㄆㄇ 的嘴型差異
- 嘴型會照瀏覽器回報的 `AudioContext.outputLatency` 往後延，補掉「畫面比聲音早」的那段；Safari 和 Firefox 沒有實作這個欄位，藍牙耳機在那兩個瀏覽器上還是會有落差
- 串流 TTS 模型是 preview，可能會變或消失；退回路徑就是原本的速度
- 語速控制是靠自然語言指示（「請用較慢的語速說」）達成，不是精確倍率
- 手機上的自動播放限制仍然存在，靠的是在送出當下先播一小段無聲音訊把 `<audio>` 解鎖（見 `public/src/app.js`）
